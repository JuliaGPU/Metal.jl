Metal Performance Shaders Graph

MPSGraphs wraps Apple's Metal Performance Shaders Graph framework. The operations below build, cache and execute graphs on MtlArrays. Metal.jl uses them to implement operations such as mul!, sort! and accumulate!; you can also call them directly.

All operations write their result into a preallocated output array. Only the matrix multiplications read it, to add β times its previous contents. They execute asynchronously, ordered with the other work submitted from the current task (kernels, copies, and other MPS or MPSGraph operations), so no synchronization is needed between them. Arrays may be views at an offset into their buffer, like contiguous views of an MtlArray.

Use MPSGraphs.supports to check a call before choosing an implementation:

using Metalusing Metal: MPSGraphsA = MtlArray(rand(Float32, 512, 1000))R = similar(A, 1, 1000)if MPSGraphs.supports(MPSGraphs.reduce!, +, R, A)    MPSGraphs.reduce!(+, R, A)else    sum!(R, A)end

MPSGraphs

Operations on MtlArrays implemented with Apple's Metal Performance Shaders Graph framework, such as MPSGraphs.reduce! and MPSGraphs.matmul!, and low-level wrappers of the framework itself, which follow Apple's API closely.

Metal.MPSGraphs.supports — Function
MPSGraphs.supports(f, args...; kwargs...)::Bool

Return whether the MPSGraph operation f supports being called as f(args...; kwargs...): whether the arguments' types, shapes, element types, memory layout and options are ones that f handles on the current device. Calling f with arguments for which this returns false throws an ArgumentError or DimensionMismatch.

The check only inspects the arguments; it does not build or run any graph. It can be used to decide whether to use an MPSGraph operation or fall back to another implementation, without duplicating the operation's requirements.

if MPSGraphs.supports(MPSGraphs.reduce!, +, R, A)    MPSGraphs.reduce!(+, R, A)else    sum!(R, A)end

Reductions and scans

Metal.MPSGraphs.reduce! — Function
MPSGraphs.reduce!(op, R, A; init=nothing) -> R

Reduce A with op along every dimension where R has extent 1 and A does not, and store the result in R, overwriting its contents.

op is one of +, *, max and min (or Base.add_sum and Base.mul_prod). R and A are MtlArrays of the same rank and the same real element type T: Float32, Float16, BFloat16, or a signed or unsigned integer of 8 to 64 bits. Each dimension of R has the extent of A in that dimension, or 1. R must not overlap A.

If init is given, it must be a T, and every element of R is op(init, x), where x is the reduction of the corresponding elements of A; init is applied exactly once. If A is empty along a reduced dimension, the result is init, or without init zero for + and one for * (max and min then require init).

The results can differ from Base.reduce:

  • floating-point sums and products are associated differently, and may round differently;
  • integer sums and products wrap around on overflow in T; they are not widened;
  • max and min propagate NaN like Base, but the sign of a zero result is unspecified (max(0.0, -0.0) may return -0.0), and a sum of negative zeros may return 0.0.

The reduction executes asynchronously, ordered with the other work submitted from the current task (kernels, copies, other MPSGraph operations).

Use MPSGraphs.supports to check whether a call is supported without throwing.

Metal.MPSGraphs.accumulate! — Function
MPSGraphs.accumulate!(op, B, A; dims=nothing, init=nothing, inclusive=true, rev=false) -> B

Compute the cumulative op of A along dimension dims, and store it in B. dims can only be omitted for vectors.

op is + or * (or Base.add_sum and Base.mul_prod), and for integers also max or min. B and A are MtlArrays of the same size and the same real element type T: Float32, Float16, BFloat16, or a signed or unsigned integer of 8 to 64 bits. B may be A, but must not otherwise overlap it.

With inclusive=true, element i along dims combines elements 1 through i of A; with inclusive=false it combines elements 1 through i-1, so the first is the identity of op. rev=true accumulates from the end instead. If init is given, it must be a T, and every result x becomes op(init, x); for an exclusive scan, the first element is init.

As with MPSGraphs.reduce!, floating-point results can round differently from Base, integer results wrap around on overflow, and the operation executes asynchronously, ordered with the other work submitted from the current task.

Use MPSGraphs.supports to check whether a call is supported without throwing.

Sorting

Metal.MPSGraphs.sort! — Function
MPSGraphs.sort!(B, A; dims=nothing, rev=false) -> B

Sort A along dimension dims in ascending order (descending with rev=true), and store the result in B. dims can only be omitted for vectors.

B and A are MtlArrays of the same size and the same real element type. B must not overlap A. Elements are ordered with isless, so NaNs sort last.

The sort executes asynchronously, ordered with the other work submitted from the current task. Use MPSGraphs.supports to check whether a call is supported without throwing.

Metal.MPSGraphs.sortperm! — Function
MPSGraphs.sortperm!(I, A; dims=nothing, rev=false) -> I

Store in I the linear indices that sort A along dimension dims, in ascending order (descending with rev=true), like sortperm(A; dims). dims can only be omitted for vectors.

A is an MtlArray with a real element type, and I an MtlArray{Int32} or MtlArray{Int64} of the same size. Elements are ordered with isless, so NaNs sort last. The permutation is not guaranteed to be stable: equal elements can appear in any order.

The operation executes asynchronously, ordered with the other work submitted from the current task. Use MPSGraphs.supports to check whether a call is supported without throwing.

Matrix multiplication

Metal.MPSGraphs.matmul! — Function
MPSGraphs.matmul!(C, A, B, α=true, β=false; tA='N', tB='N') -> C

Compute C = α * opA(A) * opB(B) + β * C, where opA and opB are the identity ('N'), transpose ('T') or adjoint ('C'), as selected by tA and tB.

A, B and C are MtlArray matrices, or 3D arrays holding equally many matrices along the last dimension, which are multiplied pairwise. A and B have the same element type, which together with that of C is one of the combinations in MPSGraphs.MPSGRAPH_VALID_MATMUL_TYPES; integer inputs are multiplied in the output type. α and β are converted to the element types of A and C. As with BLAS, C is not read when β is zero. C must not overlap A or B.

The multiplication executes asynchronously, ordered with the other work submitted from the current task. Use MPSGraphs.supports to check whether a call is supported without throwing.

source
Metal.MPSGraphs.matvecmul! — Function
MPSGraphs.matvecmul!(y, A, x, α=true, β=false; tA='N') -> y

Compute y = α * opA(A) * x + β * y, where opA is the identity ('N'), transpose ('T') or adjoint ('C'), as selected by tA.

A is an MtlArray matrix and x and y are MtlArray vectors. A and x have the same element type, which together with that of y is one of the combinations in MPSGraphs.MPSGRAPH_VALID_MATVECMUL_TYPES. Otherwise, this behaves like MPSGraphs.matmul!.

Metal.MPSGraphs.conv! — Function
MPSGraphs.conv!(y, x, w; stride=(1, 1), padding=(0, 0, 0, 0), dilation=(1, 1),
                groups=1, flipkernel=false) -> y

Compute the 2D convolution of x with the kernel w, and store it in y.

The arrays use NNlib's layout: x and y are (width, height, channels, batch), and the kernel w is (width, height, input channels ÷ groups, output channels). padding is (left, right, top, bottom). By default the kernel is flipped, i.e. this computes a convolution rather than a cross-correlation; flipkernel=true computes the latter. All arrays are 4D MtlArrays with element type Float16 or Float32.

The operation executes asynchronously, ordered with the other work submitted from the current task. Use MPSGraphs.supports to check whether a call is supported without throwing.
